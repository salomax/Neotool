# Product strategy session

1. Load the existing strategy through the Product Map or user-provided sources. Open only relevant research, decisions, and measures. Summarize the audience, intended improvement, and focus. Label sourced claims, assumptions, and open questions. If an applicable strategy is already agreed, identify the objective and return its link to the initiative.
2. When direction is unclear or needs revision, discuss the consequential choices with the user in short rounds. Ask who should benefit, what should improve, where to focus, and which trade-offs or evidence could change that focus. Offer options when they help the user decide. Carry unresolved choices as proposals or questions.
3. Draft or update the [Product Strategy template](../../../spec/templates/product-strategy.md), preserving existing objective IDs. For each objective, propose a measure and an observation window. Record unknown baselines or targets with a way to obtain them. Use the [worked example](../../../docs/examples/product-strategy.md) if a concrete example helps.
4. Ask the user to confirm which choices and objectives should guide the work. Keep pending decisions visible. Make the agreed objectives discoverable from the Product Map or existing workspace index. Hand back the objective ID and link for any initiative that advances it. If the direction still depends on evidence, hand back the question and the next action to answer it.

Keep the record at the strategy level. The initiative brief captures the opportunity and its scope. Product requirements belong in the PRD when there is behavior to define.
