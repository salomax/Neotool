# Start a Neotool initiative

1. Read the [Neotool Guideline](../../../docs/guideline.md) and [first delivery Spec template](../../../spec/templates/first-delivery.md). Load any workspace instructions and user-provided references. When resuming, read the latest records and decisions since the previous handoff before asking for information.
2. Play back the problem, audience, intended outcome, and constraints. Separate confirmed inputs from assumptions. Ask only questions that can change what gets built or how the result is judged; fill the rest from available context or mark it open.
3. Propose a small useful first delivery and explain what it would let the user verify. When a consequential choice remains unclear, frame the question, alternatives, and evidence that would resolve it. Let the user choose or amend the slice.
4. Draft context, decision, and Spec using the template. Give each acceptance criterion an ID, an observable result, and a check. Use the [worked example](../../../docs/examples/first-delivery.md) if a filled reference helps.
5. Revise the draft with the user. Hand off the agreed Spec and its references, or report the unresolved decision that prevents agreement. Implementation proceeds under the user's authorization. Evidence stays pending until checks actually run.

Use the initiative workspace or the conversation for drafts. A tracker, repository split, and hosted tools are optional.
