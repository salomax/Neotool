# Start a Neotool initiative

1. Read the [Guideline](../../../docs/guideline.md) for the routing criteria. Start with workspace instructions, user-provided inputs, and any existing initiative brief. On resumption, check the latest findings and decisions before revisiting an answered question. Follow source links only as needed for the immediate choice.
2. Reflect the idea in the user's terms: affected people, current situation, intended outcome, and constraints as known. Separate observations with sources, hypotheses, and candidate solutions. Ask a small round of questions only where the answers could change the direction. Surface contradictions and gaps instead of filling them with plausible claims.
3. Identify the uncertainty that would most change the initiative. Recommend one move from the Guideline and explain why. Frame an answerable question or design objective, the evidence or artifact expected, and what would be enough to reconsider the decision. When comparing options, agree on criteria and a baseline before rating them.
4. Shape the [Initiative Brief](../../../spec/templates/initiative-brief.md) with the user. Reuse existing records; link to claims by ID and location rather than copying them. Keep the move proposed until agreed. If no choice is possible yet, capture the unresolved question and how to get the missing input.
5. Hand off the agreed move with its question, input links, expected result, and stopping condition. Route to a relevant available skill or use the brief as the next agent's instructions. Starting the session does not itself authorize external actions or implementation. A delivery Spec belongs later, once there is behavior to define.

Use the existing workspace or conversation. A tracker and a repository scaffold are optional.
